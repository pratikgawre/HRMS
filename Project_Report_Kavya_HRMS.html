1. Executive Summary

Kavya HRMS is a full-stack Human Resource Management System designed to centralize daily HR operations, workforce administration, attendance, leave, payroll, projects, tasks, asset tracking, announcements, support tickets, interviews, and user management. The system provides role-based dashboards for Super Admin, HR Manager, Project Manager, Team Lead, and Employee users.

The frontend is implemented as a React 18 single-page application using Vite, React Router, Bootstrap, and Remix Icon. The backend is implemented with Spring Boot, MongoDB, WebSocket support, mail integration, session handling, and REST APIs. The project is suitable for internal enterprise HR operations and can be positioned as an MNC-style internal HR 360 platform.

Frontend React 18 + Vite
Backend Spring Boot 4.1
Database MongoDB
Primary Domain HR Operations

Key Capabilities

  • Role-based dashboards and navigation for all major HR personas.
  • Employee master data management with profile photo upload support.
  • Attendance recording, team attendance view, and 9 PM Asia/Kolkata auto-checkout process.
  • Leave request, approval, recommendation, and leave balance summary workflows.
  • Payroll generation from employee, attendance, and leave data with paid payslip controls.
  • Project and task assignment workflows with attachment handling.
  • Asset inventory, asset assignment, return, and employee asset request workflows.
  • Announcements, notifications, support tickets, scheduled interviews, and settings management.

Executive Conclusion

The application has a mature operational scope and a clear full-stack architecture. It already includes core enterprise workflows, backend persistence, seed data, API tests, runtime configuration, and deployment files. Recommended next steps are production hardening, secret management, formal RBAC enforcement at backend level, CI/CD, observability, and replacing any remaining local fallback data with API-only flows for enterprise-grade consistency.

3. Business Objective And Scope

Objective

The objective of Kavya HRMS is to provide a centralized platform that reduces manual HR work, improves employee service delivery, and gives managers real-time visibility into teams, attendance, leave, payroll, tasks, assets, and communication.

In Scope

  • Authentication, session validation, password reset, and forced password change flows.
  • Employee lifecycle data, profile records, HR user records, and access roles.
  • Attendance self-service and team attendance management.
  • Leave request creation, review, approval, and leave summary calculation.
  • Payroll generation, mark-paid workflow, payslip generation eligibility, and payroll records.
  • Project assignment, project teams, task assignment, task status updates, and attachments.
  • Asset inventory, assignment, return, employee asset requests, and request status changes.
  • Announcements, notifications, support tickets, interviews, settings, and seeded defaults.

Out Of Scope For Current Implementation

  • External identity provider integration such as SSO, SAML, or OAuth.
  • Advanced statutory payroll engine with country-wise tax slabs and compliance filings.
  • Centralized audit log UI in the current visible routing structure, although an audit model exists.
  • Production CI/CD, monitoring dashboards, and infrastructure-as-code are not fully present in the local repository.

6. System Architecture

Kavya HRMS uses a layered architecture. The browser loads the React SPA. Authenticated users move through role-specific protected routes and call backend APIs through a centralized frontend API client. Spring Boot receives requests, validates session tokens using Authorization bearer tokens or cookies, applies forced password change checks, executes controller/service logic, and persists documents in MongoDB.

User Browser | v React SPA - HashRouter, ProtectedRoute, DashboardLayout | v Central API Client - headers, timeout, error normalization | v Spring Boot REST Controllers - /api/* | v Interceptors - session validation, forced password change | v Service Layer - payroll, leave, email, notification, attendance jobs | v Spring Data Repositories | v MongoDB Collections + Upload Storage

Frontend Architecture

  • App.jsx defines role dashboards, public routes, protected route groups, and session bootstrap.
  • ProtectedRoute.jsx checks local session state, required password change state, and allowed role mapping.
  • DashboardLayout.jsx provides the common shell with sidebar, header, content area, login toast, and periodic access refresh.
  • Sidebar.jsx provides persona-specific menus for admin, HR, team lead, project manager, and employee users.
  • api.js centralizes API requests, timeout handling, auth headers, role headers, employee headers, and payload normalization.

Backend Architecture

  • Controllers expose REST resources for domain modules.
  • Repositories provide MongoDB CRUD and query operations.
  • Services encapsulate business logic such as payroll generation, payroll validation, leave summary, notifications, email, and attendance auto-checkout.
  • Config classes manage CORS, static upload serving, Mongo indexes, session interceptors, mail settings, and seed data.
  • WebSocket classes support live settings broadcast capabilities.

8. Application Flow

End-To-End User Flow

1. User opens the Kavya HRMS frontend. 2. React application initializes through Vite bundle and HashRouter. 3. Public route shows login, forgot-password, or change-password page. 4. User submits credentials. 5. Frontend calls POST /api/auth/login. 6. Backend validates user and creates a session token. 7. Token and user profile details are saved in session storage/local state. 8. User is redirected to the dashboard mapped to the resolved role. 9. Protected routes validate local session and allowed role. 10. DashboardLayout loads sidebar/header and refreshes users/employees periodically. 11. Module pages call REST APIs through apiRequest. 12. Backend verifies session, runs business logic, persists data, and returns JSON. 13. UI renders latest rows, summary cards, modals, toasts, validation messages, or error messages. 14. Logout or session expiry clears token and redirects user to login.

Authentication And Session Flow

Login Page -> authenticateUser() -> POST /api/auth/login -> AuthController -> AppUserRepository + AuthSessionRepository -> LoginResponse with token, role, employee identity -> startSession() -> Role dashboard redirect -> ProtectedRoute checks session on every protected route

Role Routing Flow

Team Lead /team-lead/* /team-lead/dashboard
Project Manager /project-manager/* /project-manager/dashboard

Data Flow

UI Form / Action -> Component state validation -> apiRequest(path, options) -> Headers: Authorization, X-Kavya-Access-Role, X-Kavya-User-Id, X-Kavya-Employee-Id -> Spring controller -> Service rules -> Repository save/query -> MongoDB document -> JSON response -> UI refresh / cache update / toast / error display

12. Business Rules

Attendance

  • Open attendance records are finalized automatically at 9:00 PM Asia/Kolkata.
  • Records from previous dates without checkout are also finalized.
  • Worked minutes decide status: 8 hours or more means Present, 4 to 8 hours means Half Day, below 4 hours means Absent.
  • Leave-marked attendance is excluded from auto-checkout.

Leave

  • Default leave types are Casual Leave 12, Sick Leave 10, Earned Leave 18, and Work From Home 0.
  • Current leave summary resolves employee identity from request headers or user mapping.
  • Only approved leave requests count as taken leave.
  • Remaining balance is total allotted minus approved taken days, never below zero.

Payroll Generation

  • Payroll generation runs for selected month and year for all active employees.
  • Annual packages of 300000 or more are converted to monthly gross by dividing by 12.
  • Attendance and approved leave are summarized before payroll calculation.
  • Absent and half-day deductions are based on per-day salary.
  • PF is calculated when PF/UAN exists, using 12 percent of 50 percent of monthly gross.
  • Gratuity and professional tax are included in deduction summary.

Payroll Validation

  • Already paid records cannot be marked paid again.
  • Future payroll periods cannot be marked paid.
  • Current month mark-paid is disabled after day 15.
  • Payslip generation is allowed only for paid records with positive net salary.

Session

  • Session token is accepted from Authorization bearer token or kavyaAuthToken cookie.
  • Session expires after 1 hour from the latest seen timestamp.
  • Expired or missing sessions return 401 and clear the auth cookie.
  • Public auth endpoints include login, forgot password, reset password, and session delete.

Settings

  • Default company settings use Asia/Kolkata timezone.
  • Default working hours are 09:00 AM to 06:00 PM.
  • Default week off is Sunday.
  • Default payroll cutoff is the 25th of every month.

13. Security And Session Management

Implemented Controls

  • Protected frontend routes enforce role-level access before rendering pages.
  • Backend interceptors enforce authenticated session validation across /api/**.
  • Forced password change interceptor is registered for API routes.
  • API requests include Authorization bearer token, user ID, employee ID, and access role headers.
  • CORS is restricted to configurable origin patterns, defaulting to localhost development patterns.
  • Uploaded resources are served through a dedicated /uploads/** resource handler.
  • API client normalizes errors and clears stale session state on unauthorized backend responses.

Security Recommendations

Area Recommendation Priority
Password Storage Ensure all persisted passwords use strong one-way hashing and remove plaintext fallback/password fields in production. High
RBAC Mirror frontend permission checks on backend endpoints so users cannot bypass access through direct API calls. High
Secrets Store SMTP, SendGrid, database, and deployment secrets only in environment variables or a secret manager. High
Audit Use the existing AuditLog model to capture sensitive changes such as payroll, role, employee, and settings updates. Medium
Session Consider refresh-token rotation, device/session management UI, and stricter cookie security in production HTTPS. Medium

Frontend Build And Hosting

  • Vite production build command: npm run build.
  • Netlify configuration uses Frontend as base, dist as publish directory, and routes all paths to /index.html.
  • Vite dev server runs at 127.0.0.1:5173 and proxies /api and /uploads to the backend.

Backend Container

  • Multi-stage Docker build uses Maven with Eclipse Temurin 17 to package the backend JAR.
  • Runtime image uses Eclipse Temurin 17 JRE.
  • Dockerfile exposes port 10000 and starts java -jar app.jar.
  • Production should align platform port variables with Spring SERVER_PORT configuration.

Mail Configuration

  • SMTP is controlled through environment variables such as SMTP_HOST, SMTP_PORT, SMTP_USERNAME, SMTP_PASSWORD, and SMTP_FROM.
  • SendGrid is configurable through SENDGRID_API_KEY, sender variables, API URL, and timeout variables.
  • Email features include password reset, employee welcome/credential emails, and interview notification emails.

16. Risks, Recommendations, And Future Scope

Category Observation Recommendation
Security Demo credentials and local fallback authentication are convenient for development. Disable demo fallback in production builds and require secure backend-only authentication.
Authorization Frontend role routing is strong for UX, but enterprise systems need backend-enforced role permissions. Add centralized backend RBAC annotations/services across controllers.
Payroll Payroll rules are operational but simplified. Add configurable earning/deduction components, statutory tax rules, audit approval, and payroll lock periods.
Deployment Frontend Netlify and backend Docker are present, but full infrastructure pipeline is not present. Add CI/CD, environment separation, health checks, and release rollback process.
Observability Application logs exist through Spring logging, but central monitoring is not visible in the repo. Add structured logs, metrics, tracing, error tracking, and alerting for production readiness.
Data Governance HRMS stores sensitive employee, identity, payroll, and document data. Add data retention policy, audit trail UI, export controls, backup/restore procedure, and access review.

Future Scope

  • Single sign-on with Microsoft Entra ID, Google Workspace, or SAML provider.
  • Multi-level approval chains for payroll, leaves, assets, and employee changes.
  • Advanced analytics for attrition, attendance trends, project staffing, and payroll forecasting.
  • Employee document vault with verification workflow.
  • Mobile-first employee self-service experience.
  • Manager scorecards and performance review cycles.
  • Compliance reports, audit exports, and maker-checker approvals for sensitive records.

17. Conclusion

Kavya HRMS is a comprehensive HR operations platform with a meaningful enterprise scope. It includes a modern React frontend, Spring Boot backend, MongoDB persistence, role-based flows, operational modules, payroll and attendance business logic, file upload support, mail integration, seeded defaults, and a deployable structure.

The project is well positioned as an internal MNC-style HR 360 application. With additional production hardening around security, backend authorization, audit logs, CI/CD, monitoring, and statutory payroll compliance, it can evolve into a robust enterprise-grade HRMS platform.
